# CDC — Brique 4a : suite après la Brique 4 (dépôt)

**Rôle** : tracer le travail **restant ou ultérieur** une fois le périmètre [`CDC-BRIQUE-4.md`](./CDC-BRIQUE-4.md) + [`CDC-BRIQUE-4-CHECKLIST.md`](./CDC-BRIQUE-4-CHECKLIST.md) couvert dans le code — **sans** référence à une grille « 95 points » (erreur, à ne plus utiliser).

**Brique 5** (correcteur, etc.) : **CDC séparé** — voir [`CDC-BRIQUE-5.md`](./CDC-BRIQUE-5.md) ; ne pas mélanger ici.

---

## Ce que 4a n’est pas

- Ce n’est **pas** une seconde checklist à 120 cases : c’est un **backlog** vivant.
- Ce n’est **pas** un engagement de version : les items sont **priorisés par le produit**.

---

## Pistes typiques (à cadrer au fil des releases)

| Zone | Exemples |
|------|----------|
| **Release Windows** | Installateur, signature, mises à jour in-app, build CI |
| **Terrain imprimeur** | Épreuves réelles, retours sur PDF/X, profils ICC affinés |
| **Moteur print / média** | Kerning GPOS, heatmap pleine résolution, mockup 3D si besoin marché |
| **Robustesse** | Tests E2E exports, gros manuscrits, erreurs réseau génération image |
| **UX** | Assistances pas-à-pas imprimeur, tutoriels vidéo |
